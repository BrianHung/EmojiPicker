# Changelog

## Unreleased

The React layer runs on React Aria (`react-aria-components` and its hooks) instead of emoji-picker-react; `emoji-picker-react` is no longer a dependency. The public API (parts, hooks, props) is unchanged except as listed here.

### Semantics

- The grid is a `listbox` of `option`s in `group`s (one per section, named by its title), not a `grid` of `gridcell`s. `aria-posinset` and `aria-setsize` count within a section.
- The search field is a `searchbox` (React Aria `Autocomplete`, virtual focus) instead of a `combobox`; it has no `aria-expanded`.
- A tapback's reactions are a `toolbar` of buttons (toggle buttons with `aria-pressed` when `selected` is given), not a `list`.
- Category tabs have no `aria-controls` (they scroll one list rather than switch panels).
- Each part handles its own keys with React Aria and stops the ones it handles, so a key the List handles doesn't reach Root's `onKeyDown`. A part's `onKeyDown` runs before its handler; `event.preventEmojiPickerHandler()` (Base UI's `preventBaseUIHandler`) skips the picker's handling of that key, and `event.preventDefault()` keeps its usual meaning. Keyboard and pointer move one highlight; the pointer moves it only when it moves, not when the list scrolls under it. Escape with nothing to clear or close goes on to the page (a sheet or dialog around the picker closes).
- The search field's clear button is rendered only while there is a query.
- Keyboard moves scroll only the picker's own viewport, never the page.
- With `List.SectionActions`, Tab from an emoji goes to the next section's actions (Shift+Tab: its own), as if they were in reading order.
- `EmojiPopover`: Tab out of the content (also from a toolbar inside, which moves focus itself) returns to the page after the trigger and closes.
- `EmojiPopover` (both adapters): a picker with no search field to focus focuses its current emoji once its grid renders; the trigger has `aria-haspopup="dialog"` and `aria-expanded`; the content sets `--available-height`, which a picker's `max-height` can use to fit the space left and scroll inside.

### Added

- Framework-neutral state in `/core`: `createEmojiSuggestions(store, options)` (the `:shortcode` typeahead: `setQuery`, `move`, `highlight`, `choose` (`{ record: false }` inserts without counting the emoji as used, for a menu whose picker already did), `dismiss`, IME-safe `keydown`, and `getInputProps` / `getListProps` / `getOptionProps` attribute getters) and `createPickerState(store, options)` (query and results, sections from categories, frequents and collapse, highlight, hover, current section, variations, virtual or roving focus; `moveHighlight` moves through the grid; the highlight is its own unless controlled with `highlight` and `onHighlightChange`). Both are `subscribe` / `getSnapshot` stores; `useEmojiSuggestions`, `useEmojiSearch`, Root and the List are thin React wrappers over them, with the same API.
- One `locale` for everything: `createEmojiStore` (and `EmojiProvider`) take `labels`; `store.labels()` is the labels for the locale (counts in its digits and plural rules); `localizeLabels(locale, overrides)` builds them. Without `locale`, the dataset's is used for search, collation and counts. Each piece (`labels`, `data`, `search`, shortcode sets) replaces only itself.
- `EmojiItem`, `EmojiSection`, `CategoryOption` (with a generic icon type) are exported from `/core`.

- Editor typeahead: `useEmojiTypeahead(trigger, options, element)` turns any editor's `:query` (`query`, `anchor`, `replace`) into one `EmojiTypeahead` (`query`, `open`, `anchor`, `suggestions`, `dismiss`, `onKeyDown`) that any menu renders, and makes the editor a combobox while it is open. `useTextFieldEmojiTypeahead` adapts it to input and textarea (caret rect from `dom-input-range`, insertion keeps the browser's undo). `findShortcodeTrigger(text)`: the `:query` the text before the caret ends with.
- `useEmojiTypeaheadStore(create, deps)` renders a framework-neutral typeahead (`suggestions`, `anchor()`, `keydown`) as an `EmojiTypeahead` in React.
- `useEmojiGrid`: the List's grid for a virtualizer you bring (TanStack Virtual, react-window, Virtuoso): `rows`, `stickyIndexes`, prop getters, and `scrollToIndex`. `createEmojiGrid`, `moveInGrid` and `rowsPerPage` (also in `/core`): the rows and the keyboard without React.
- Root `actionsRef` and `useEmojiPickerActions()`: `move`, `pick`, `highlight`, `focusSearch`, `clearSearch`, `close` and `toggleSkinTone`. Root `keyboardTarget`: an element that keeps focus, such as an editor, whose arrows, Page Up/Down and Enter drive the picker; it gets `aria-activedescendant` and `aria-controls`.
- `List.SectionActions` (state: `section`, `collapsed`, `toggle`, `toggleProps` with `aria-expanded`): controls for a section title, rendered outside the listbox and pinned with the sticky title.
- `pickerInitialFocus(root)`: where focus belongs when a picker opens in any popover (Base UI, Radix, shadcn/ui).
- `ReactionBar`: React Aria's `Toolbar` with Home/End and hover continuity, for rows of your own reaction buttons.
- `Root reactions` (the user's most-used emoji from `useFrequentEmoji({ limit }).items`, or fixed ones) with `EmojiPicker.Reactions` and `EmojiPicker.Panel` replace `Tapback`: `Reactions selected` marks the user's reactions, `Reactions.Expand` shows while a `Panel` is rendered, and `onSelect`'s `details.collapse()` shows the row again. The registry's `EmojiTapback` is the preset.
- `Root columns`: `"fit"` (default) fits the width, a number is exactly that many per row (replaces `fitColumns`).
- `List renderEmptyState({ status, query, error, retry })`, React Aria's name: what the list shows while data loads, after it fails and when a search has no results (replaces `Empty`, `Loading` and `LoadError`, and the `noResults`, `loading`, `loadingError` and `retryLoading` labels).
- Every controllable state's `onXChange` receives `(value, details)`, as Base UI's: `details.reason`, `details.event` and `details.cancel()`, which keeps the state as it is. Root `query`, `value`, `highlight`, `collapsedCategories` and `reactionsOpen`; `SkinTone open`; the provider's `skinTone` and `frequents`; `EmojiPopover.Root open` and `EmojiSuggestions.Popover` (`"trigger-press"`, `"outside-press"`, `"escape-key"`, `"item-press"`, `"focus-out"`, `"scroll"`, `"none"`, in both adapters). Core `createChangeDetails(reason, event)` builds them.
- Frequently used emoji are state you can own: the provider's `frequents` / `defaultFrequents` / `onFrequentsChange(entries, { reason: "pick" | "remove" | "clear", emoji })` with serializable `Record<unified, { count, lastUsed }>` entries (`count` is the decayed use count as of `lastUsed`, halving every 14 days), tuned by `frequentsHalfLifeDays` and `frequentsMax`, persisted by `frequentsStorage` (localStorage `emoji-picker:frequents` by default, synced across tabs; `null` for memory). `useFrequentEmoji({ limit })` returns `{ items, record, remove, clear }`. Core `mergeFrequents(a, b)` merges two histories. Replaces passing a `FrequencyStore` from `createFrequencyStore`.
- Typeahead `onSelect(selection)` (`useEmojiTypeahead`, `useTextFieldEmojiTypeahead`, core `createEmojiSuggestions`): an `EmojiSelection` once a suggestion is chosen.
- `skinToneStorage` and `frequentsStorage` follow other tabs (`EmojiStorage.subscribe`).
- `--emoji-list-padding-end`: the grid's end padding without `columns`.
- `Root value`: a value picker (`selectionMode="single"`, `aria-selected`).
- `EmojiProvider locale` sets React Aria's locale (`I18nProvider`: direction, number formatting) and formats the default result count; every string in `EmojiLabels` is used (`labels` takes any of them).
- Data attributes on cells and tabs, as React Aria names them: `data-focused`, `data-focus-visible`, `data-hovered`, `data-pressed`, `data-selected`, `data-index`.

- The provider follows its props: changing `data`, `locale`, `filter`, `customEmojis` or `searchEngine` updates the store in place (frequents and skin tone stay; the old data shows until new data loads), so a `key` remount is no longer needed. A dataset object is ready on the first render, so server-rendered markup has the grid.
- Zero-config: `data` defaults to core's `data/en.json` on jsDelivr, pinned to core's version, and `EmojiPicker.Root` creates a provider when none is above it.
- `data` takes a hand-written `EmojiDataInput` (`{ locale, groups: [{ id, label }], emojis: [{ emoji | unified, label, tags?, shortcodes?, group, version? }] }`), normalized to the compact format on load. Core's `localeData(locale, { shortcodes, baseUrl })` returns the URL of a prebuilt dataset in `@brianhung/emoji-picker-data`.
- Each part is exported on its own (`EmojiPickerRoot`, `EmojiPickerSearch`, `EmojiPickerList`, …) beside `EmojiPicker.*`, for bundlers that keep whole namespace imports.
- The List sets `--emoji-picker-content-width` on Root to its measured width.

### Changed

- Every part takes `render` (an element whose props and ref merge with the part's, or `(props, state) => element`, as Base UI's; built on React Aria's `composeRenderProps` and `mergeProps`), and `className` and `style` as values or functions of the part's state. State is also on data attributes, as before. `EmojiPopover.Trigger asChild` and `SearchInput as` are removed: use `render`.
- The defaults are parts you can compose: `Search.Input` (the field) and `Search.Clear`; `SkinTone.Trigger`, `SkinTone.Options` (`(tone) => …`), `SkinTone.Option` and `SkinTone.Glyph` (an emoji in the option's tone, ✋ by default; the trigger has `data-slot="emoji-picker-skin-tone-trigger"`); `Reactions.Items`, `Reactions.Item` and `Reactions.Expand`. A `Search` or `SkinTone` with children renders only them. Removed: `SearchInput` (use `Search.Input`), `Search inputProps` and `inputRef`, `SkinTone emoji`, `button`, `buttonClassName` and `optionsClassName`, `Tapback reactionsClassName`, and `components.ClearButton`, `ExpandButton` and `SkinToneButton` (with `SkinToneButtonProps` and `SkinToneId`).
- Collections render through children functions, called only for what is in view: `List` takes `(section) => <List.Section>` with `List.SectionTitle`, `List.Items` (`(emoji) => <List.Cell />`) and `List.SectionActions`; `CategoryNav` takes `(category) => <CategoryNav.Tab />`. Left out, each renders its default. A cell's state (`highlighted`, `active`, `hovered`, `focused`, `focusVisible`, `pressed`, `selected`, `emoji`) reaches its `className` and `style`. Removed: `components` on Root and List (`PickerComponents`, `ListComponents`, `EmojiCellProps`, `CategoryHeaderProps`, `HeaderActionsProps`, `CategoryButtonProps`, `ListEmoji`), and `cellClassName`, `headerClassName` and `tabClassName`.
- A highlight or hover move re-renders only the cells it leaves and enters (and what shows the active emoji): the highlight lives in the core state, each cell subscribes to its own, and the List and Root don't; the cell it lands on takes focus or virtual focus itself. `useEmojiCell(state, item)` does the same for `useEmojiGrid`'s cells (`useEmojiGrid` returns `state`; `getCellProps` is removed).
- `EmojiPopover.Content finalFocus` (both adapters; Base UI's name): where focus goes once a pick closes the content, instead of the trigger (other closes return to it). An element, a ref, or a function returning one.
- Skin-tone variations per emoji (Shift+Space on the highlighted or focused emoji, or a long press) open a row of its six tones over it: a `listbox` (`data-slot="emoji-picker-variations"`, options `data-slot="emoji-picker-emoji"`) named by `labels.skinTone`, focused on the current tone; Left/Right, Home and End move along it, Enter or Space picks, Escape closes back to the emoji. `Root disableVariations` turns them off.
- No injected CSS: the structural stylesheet, the forced-colors stylesheet and `Root cssLayer` and `nonce` are gone. What a part needs to lay out is inline and driven by the size variables (a cell's size, a title's height, the viewport's scroll axis, the column sizer for `columns`, a skin-tone menu's `position: absolute`, a hidden Panel); everything visual is your classes (see the registry item): the Root's flex column, a cell's centering, the emoji font (`--emoji-font-family`, defaulted in `tokens.css`), forced-colors outlines, reduced motion, a popover's `max-height: var(--available-height)`.
- Controlled state, Base UI style: Root `query` / `defaultQuery` / `onQueryChange` (was `search` / `defaultSearch` / `onSearchChange`), `value` / `defaultValue` / `onValueChange` (was `List value`, and `useEmojiGrid`'s), `highlight` / `defaultHighlight` / `onHighlightChange(emoji, { reason, event })` (`reason` is `"keyboard"`, `"pointer"` or `"none"`, as in Base UI's `onItemHighlighted`), and `reactions` with `reactionsOpen` / `defaultReactionsOpen` / `onReactionsOpenChange` (Root has `data-reactions-open`). The provider's skin tone: `skinTone` / `defaultSkinTone` / `onSkinToneChange`, persisted by `skinToneStorage` (localStorage `emoji-picker:skin-tone` by default, `null` for memory). Core `createPickerState` takes `query`, `defaultQuery`, `onQueryChange` and `defaultHighlight`.
- One vocabulary across parts: Root's `data-search` is `data-searching`, also on Viewport and List; `Search.Input`, `Search.Clear`, `Reactions.Item` and `Reactions.Expand` pass `{ hovered, focused, focusVisible, pressed, disabled }` (and `selected` on an item) to `className`, `style`, `render` and `children`, as the cells and tabs do, instead of React Aria's `isHovered`-style render props. `EmojiPopover.Content` takes `className` and `style` as functions of `{ open, side, align }` (both adapters).
- Tighter types: `ElementProps<E>` (what `render` receives) is typed to the part's element instead of `any`; skin tones are `SkinToneValue` (`0 | 1 | 2 | 3 | 4 | 5`) in the provider, `useSkinTone`, the SkinTone parts and `EmojiSelection`; `CategoryOption.id` is a `CategoryId` (a group, `"suggested"`, `"custom"` or `` `custom:${string}` ``); `onCollapsedCategoriesChange` receives a `readonly string[]`. `EmojiGridState` (from `useEmojiGrid`, for `useEmojiCell`) is opaque,.
- `SkinTone` takes `open` / `defaultOpen` / `onOpenChange`. State attributes match each part's state: `data-empty` on Search, `data-disabled` on CategoryNav, `data-state` on `SkinTone.Trigger`, `data-selected` on the current `SkinTone.Option`, `data-collapsed` on `List.SectionActions`.
- Renamed: the provider's `search` engine is `searchEngine`; the `useEmojiSuggestions` state type is `EmojiSuggestionsState` (`EmojiSuggestions` is only the value, `EmojiSuggestions.Popover`); `FrequencyStorage` is `EmojiStorage`; `useSearchState()` returns `query`.
- Every `data-slot` but the root's (`emoji-picker`) starts with `emoji-picker-`, so they don't collide with shadcn/ui's (`empty`, `popover-content`): `emoji` is `emoji-picker-emoji`, `search-input` is `emoji-picker-search-input`, and so on; `category` and `category-header` are `emoji-picker-section` and `emoji-picker-section-title`, and `header-actions` is `emoji-picker-section-actions` (the `List.Section` parts); `EmojiPopover`'s `popover-trigger` and `popover-content` are `emoji-picker-popover-trigger` and `emoji-picker-popover-content`, and `suggestions-popover` is `emoji-picker-suggestions-popover`.
- `useTextFieldEmojiTypeahead` opens on a field that starts with a `:query` (caret taken at the end while unfocused), until focus first lands elsewhere.
- The package ships one module per source file: a bundler loads only what you import (`Emoji` alone is ~8 KB gzipped over React; the popover and tapback load only when used).

- One image path: `Renderer` is `"native" | "image"`, and the provider's `renderer` also takes `"auto"` (images only where the system can't draw emoji). Image emoji come from the provider's `imageUrl(unified, { renderer })`, which returns a URL or `undefined` for native text (Twemoji under the image renderer by default), capped at emoji version `imageVersion` (17 by default); returning a URL under the native renderer replaces particular emoji with your own artwork (`data-overridden`). Replaced: the `"twemoji"` renderer (`"image"`), `twemojiBaseUrl` (`imageUrl={(u, { renderer }) => renderer === "image" ? twemojiUrl(u, base) : undefined}`), `twemojiVersion` (`imageVersion`), `EmojiOverrides`, `findArtwork`, `Artwork` and `ArtworkMap` (`imageUrl`), and core's `needsTwemoji` (internal).

### Removed

- `Tapback` and `TapbackProps` (Root `reactions`, `Reactions selected`; the `EmojiTapback` registry item), `EmojiPicker.Empty`, `Loading` and `LoadError` (`List renderEmptyState`), `fitColumns` (`columns`), `useEmojiSearchState` (`useEmojiSearch` returns `{ results, pending }`), `EmojiOverrides` (`imageUrl`), `createFrequencyStore`, `DEFAULT_FREQUENT` and `FrequencyStore.version()` (the provider's `frequents`), `useEmojiPopover` (`useEmojiPickerActions().close()`), the store's `search()` (`query()`) and `collator` (`locale`), and the `data-layout` and `data-selection-mode` attributes. Core no longer exports the native-support probe (`nativeProbe`, `needsImageFallback`, …), `indexFor` or `SearchIndexOptions`.

- Editor adapters are registry items instead of subpaths: `emoji-tiptap.json` (`useTiptapEmojiTypeahead`), `emoji-lexical.json` (`useLexicalEmojiTypeahead`) and `emoji-prosemirror.json` (`emojiTypeahead`, formerly `@brianhung/emoji-picker-core/prosemirror`), added with `npx shadcn@latest add https://emoji.brianhung.me/r/<item>.json`. Tiptap, Lexical and ProseMirror are no longer peer dependencies.
- `fuse()` from `@brianhung/emoji-picker-core/search`: core holds no adapters for libraries it doesn't depend on. The core README has a self-contained Fuse.js recipe, beside MiniSearch and FlexSearch.
- Root `searchPlaceholder` and `autoFocusSearch` (`Search.Input` takes `placeholder` and `autoFocus`), `artwork` (the provider's `imageUrl`), `colorScheme`, `cssLayer` and `nonce`; `useSearchActions` (control `query`); `useShortcodeAutocomplete` and its types (`useTextFieldEmojiTypeahead`).

- Output no longer contains emoji-picker-react markup (`epr-*` classes, `data-epr-*` attributes, `--epr-*` variables). Style `data-slot` and `data-*` attributes; CSS that targeted `[data-epr-part=category-content]` maps to `columns` and `--emoji-list-padding-end`.
