## Usage

Each custom emoji is an `id`, a `name`, an `imageUrl`, optional `shortcodes` and `tags`, and a `group` that becomes its own section.

```tsx title="app.tsx"
const bufo = await fetch("/packs/bufo/pack.json").then((r) => r.json());

<EmojiProvider data="/emoji/en.json" customEmojis={bufo}>
  <EmojiPicker.Root categories={[{ id: "custom:Bufo" }, { id: "smileys_people" }]}>
    …
  </EmojiPicker.Root>
</EmojiProvider>
```

## Host a pack

A pack is a `pack.json` served as a static file and fetched at runtime, so it stays out of the JS bundle. A pack served from your own origin needs no CORS headers. This site's [example pack](/packs/bufo/pack.json) references its images on all-the.bufo.zone.

`customEmojis` also takes the array itself, or a loader that fetches through your own API, so the browser never requests another origin. Images load as `<img>` elements, which need no CORS. Under a strict Content Security Policy, self-host the images and set each emoji's `imageUrl` to your copy.

```json title="pack.json"
[
  {
    "id": "bufo-party",
    "name": "bufo party",
    "imageUrl": "https://all-the.bufo.zone/bufo-party.gif",
    "shortcodes": ["bufo-party"],
    "group": "Bufo",
    "width": 128,
    "height": 128,
    "animated": true
  }
]
```

## Load a pack by URL

Enter a `pack.json` URL to load it. A pack on another origin must be served with CORS. Relative `imageUrl`s resolve against the pack's URL.

## Large packs

- Fetch the pack by URL after the page loads, and keep it out of the bundle.
- Ship small thumbnails (64px WebP is about 2 KB each).
- The grid is virtualized, so only visible cells request images.
- Animated GIFs play in the grid. Mark them `animated: true`, and add a `stillUrl` to show under reduced motion.
- Give each emoji a readable `name` (“party parrot”, not `partyParrot`) so every word is searchable.
