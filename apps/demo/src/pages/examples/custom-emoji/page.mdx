## Usage

Each custom emoji is an `id`, a `name`, an `imageUrl`, optional `shortcodes` and `tags`, and a `group` that becomes its own section.

```tsx title="app.tsx"
const bufo = await fetch("/packs/bufo/pack.json").then((r) => r.json());

<EmojiProvider data="/emoji/en.json" customEmojis={bufo}>
  <EmojiPicker.Root categories={[{ id: "custom:Bufo" }, { id: "smileys_people" }]}>
    …
  </EmojiPicker.Root>
</EmojiProvider>
```

## Host your own pack

A pack is a `pack.json` served as a static file and fetched at runtime, so it stays out of the JS bundle. Serve it from your own origin and no CORS is involved. This site's [example pack](/packs/bufo/pack.json) references its images on all-the.bufo.zone.

`customEmojis` also takes the array itself, or a loader that fetches through your own API, so the browser never requests another origin. Images load as `<img>`, which needs no CORS; under a strict Content-Security-Policy, self-host them too, and point `imageUrl` at your copy if you render images.

```json title="pack.json"
[
  {
    "id": "bufo-party",
    "name": "bufo party",
    "imageUrl": "https://all-the.bufo.zone/bufo-party.gif",
    "shortcodes": ["bufo-party"],
    "group": "Bufo",
    "width": 128,
    "height": 128,
    "animated": true
  }
]
```

## Bring your own pack

Try any `pack.json` URL. A pack on another origin must be served with CORS. Relative `imageUrl`s resolve against the pack's URL.

## Large packs

- Fetch the pack by URL after the page loads; keep it out of the bundle.
- Ship small thumbnails (64px WebP is about 2 KB each).
- Only visible cells request images: the grid is virtualized.
- GIFs animate in the grid. Mark them `animated`.
- Give each emoji a readable `name` (“party parrot”, not `partyParrot`) so every word is searchable.
