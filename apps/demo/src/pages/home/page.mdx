### Shared provider {#provider}

`Root` uses the nearest `EmojiProvider` and creates its own when there is none. Hoist one provider to share data, locale, custom emoji, skin tone and frequently used emoji across every picker, reaction row and typeahead below it. `EmojiTapback`, `Emoji`, the typeahead hooks, and `useSkinTone` or `useFrequentEmoji` outside a `Root` require one.

### Emoji data {#data}

`en.json` ships with core: 1,923 emoji from Emojibase with Slack shortcodes. By default it loads from jsDelivr, pinned to the installed core version. To self-host, serve the file and pass its URL. `data` also takes a loader or the dataset object, and `filter` removes emoji from pickers and search.

<CodeTabs>

```tsx title="app/providers.tsx" label="Self-hosted"
// cp node_modules/@brianhung/emoji-picker-core/data/en.json public/emoji/en.json
<EmojiProvider data="/emoji/en.json">
```

```tsx title="app/providers.tsx" label="Loader"
<EmojiProvider data={({ signal }) => fetch(`/emoji/${locale}.json`, { signal }).then((r) => r.json())}>
```

```tsx title="app/providers.tsx" label="Filter"
<EmojiProvider filter={(e) => e.group !== "flags" && e.version <= 15}>
```

#### Keyboard

Each part handles its own keys with React Aria. A part's `onKeyDown` runs before the picker's handler; `event.preventEmojiPickerHandler()` skips it for that key, and `event.preventDefault()` keeps its usual meaning. Keyboard and pointer move one highlight. With a search field focus stays in it (`aria-activedescendant`); without one, focus moves through the cells.

To drive the picker from an editor that keeps focus, pass it as `keyboardTarget`, or call the actions from `actionsRef` (`useEmojiPickerActions()` inside Root).

```tsx title="editor-menu.tsx"
const actions = React.useRef<EmojiPickerActions>(null);

<EmojiPicker.Root query={query} keyboardTarget={editor.view.dom} actionsRef={actions} onKeyDown={(e) => e.key === "Escape" && e.preventEmojiPickerHandler()}>
  …
</EmojiPicker.Root>;

actions.current?.move("down");
actions.current?.pick();
```

#### Floating UI or React Aria

`EmojiPopover`, `EmojiSuggestions.Popover` (a `:shortcode` menu at a text field's caret that never takes focus) and `pickerInitialFocus` come from either subpath; an app bundles only the one it imports. React Aria's popover is modal: focus stays inside and the page doesn't scroll until it closes. Its non-modal popover closes when the page scrolls and stays open on a press outside, so editor menus should use the Floating UI `EmojiSuggestions.Popover`.

```tsx title="imports.tsx"
import { EmojiPopover, EmojiSuggestions } from "@brianhung/emoji-picker-react/floating-ui"; // the default
import { EmojiPopover, EmojiSuggestions } from "@brianhung/emoji-picker-react/react-aria";
```

#### Your own popover

A picker works in any popover. Close it from `onSelect`, and give the search field `autoFocus`. A picker without a search field takes `pickerInitialFocus` (from either popover subpath) as the popover's initial focus.

```tsx title="emoji-button.tsx"
import { Popover, PopoverContent, PopoverTrigger } from "@/components/ui/popover";
import { EmojiPicker } from "@brianhung/emoji-picker-react";

<Popover open={open} onOpenChange={setOpen}>
  <PopoverTrigger>😀</PopoverTrigger>
  <PopoverContent>
    <EmojiPicker.Root onSelect={({ emoji }) => { insert(emoji); setOpen(false); }}>
      <EmojiPicker.Search>
        <EmojiPicker.Search.Input autoFocus />
      </EmojiPicker.Search>
      …
    </EmojiPicker.Root>
  </PopoverContent>
</Popover>
```
